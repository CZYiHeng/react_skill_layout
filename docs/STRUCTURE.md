# 文档体系规则（STRUCTURE）

> 版本：v1.0
> 状态：**当前有效**（元规则；本仓库所有文档按此管理）
> 入口：[AGENTS.md](../AGENTS.md)

本文件规定**文档怎么记、什么算权威**。改文档前先读本文件。

---

## 1. 六层分工（各司其职，不越界）

| 层 | 落点 | 只放什么 | 改的频率 |
|---|---|---|---|
| **入口** | `AGENTS.md` | 读序、不变量、文档索引 | 极少 |
| **规则** | `docs/STRUCTURE.md`（本文件） | 文档体系的元规则 | 极少 |
| **现状** | `docs/DESIGN.md` | 系统**当前**架构、协议、安全模型 | 每次实施完成后 |
| **过程** | `docs/changes/*.md` | 一次改造的动机、依据、取舍、实施、验收 | 一次性（写完基本不改） |
| **索引** | `docs/changes/index.md` | 变更清单 + 状态列 | 每新增一份 |
| **手册/待办/素材** | `使用指南.md` / `BACKLOG.md` / `docs/demo-brief.md` | 各自的单一职责 | 按需 |

**判断归位的一句话**：写的是"一次改造"→ `docs/changes/`；写的是"系统长什么样"→ `DESIGN.md`；
写的是"以后都该怎么记"→ 本文件。**不要把过程文档的内容搬进现状文档**——现状文档只描述结果。

---

## 2. 权威判定规则

1. **状态为「当前有效」的最新的那条变更文档 = 实施依据。** 冲突时按此判定，不按文件名或日期猜。
2. **「已被取代」的只看留痕**，不作为实施依据（保留原文是为了记录"当时为什么那么定"）。
3. **`DESIGN.md` 是现状的唯一权威**；过程文档与它冲突时以 `DESIGN.md` 为准（现状是实施后的结果）。
4. **同一主题出现新文档时，必须让旧文档指向新文档**（在旧文档头部写 `取代`，在新文档头部写 `取代：<旧文档>`）。**双向声明，缺一不可**——单向的话，先读到旧文档的人就会被误导。
5. 本文件与 `AGENTS.md` 冲突时，以 `AGENTS.md` 为准（它更薄、更靠入口）。

---

## 3. 状态字段规范

所有 `docs/changes/*.md` 头部**必须**有这四行（用引用块）：

```markdown
> 版本：v1.0
> 状态：**当前有效**
> 日期：2026-09-29
> 取代：<被本文取代的文档>（可选；无则省略该行）
```

`状态` 的取值**只有四种**：

| 取值 | 含义 | 可否作为实施依据 |
|---|---|---|
| **当前有效** | 已定稿，实施以它为准 | ✅ |
| **实施中** | 正在按它改代码 | ✅ |
| **部分取代** | 本文某几节已被更新文档取代，头部须写明是哪几节、由谁取代 | ✅（仅未被取代的部分） |
| **已被取代** | 全部内容由更新文档取代 | ❌ 仅作留痕 |

**"部分取代"必须写明范围**，例如：

```markdown
> 状态：**部分取代**（§2.5 编码段实施顺序由 2026-09-29-agent-architecture.md 取代）
```

不写范围的话，等于逼读者去猜哪节还有效——这正是本规范要消灭的情况。

---

## 4. 登记流程（新增一份变更文档时）

1. 头部写齐 §3 的四行。
2. 在 `docs/changes/index.md` 表格里加一行，**状态列填 §3 的取值**。
3. 若取代了旧文档 → 回到旧文档头部加 `状态：已被取代（由 <新文档> 取代）`，做到 §2.4 的双向声明。
4. 引用的代码位置**逐一核实**（`file:line` 必须指向写的那样东西）。
5. 实施步骤必须带**反向验证**方式（怎么故意破坏、断言如何变红）。

---

## 5. 为什么这么严（真实代价）

本仓库发生过三类可复现的事故，都是文档管理缺失导致的：

| 事故 | 后果 |
|---|---|
| 存在一份 378 行的 `coding` 计划，却从零另写架构文档 | 两份对同一件事给出相反结论（8 字段头去留） |
| 变更文档之间无取代声明 | 先读到旧文档的人按旧结论实施 |
| 文档里写代码位置凭记忆 | 引用过 `react/testing.py`（**该文件不存在**，真实是 `react/model.py` 的 `MockClient`） |

所以 §2/§3 的严格不是形式主义，是针对这三类事故的防线。
